# Using Rendered Realms

Choose Thor, Loki or Odin at the top. Their modeled relic and five council members change with the selection. Type in the conversation and press Send or Enter; Shift+Enter adds a line. On a phone, Chat brings the composer into view. Existing listening and spoken-output settings retain their separate roles.

## Arsenal

Open Arsenal or Ctrl/Cmd+K. It has four sections:

1. **Backend tools:** Search the real backend catalogue or choose a category. Tools are filtered for the current persona (Thor 209, Loki 176, Odin 193; 223 unique across the three). Open a tool, fill its fields and choose Prepare request. Review the composer and Send when ready. Service configuration and permissions are checked by the existing backend when used.
2. **Local tools:** Run any of 36 calculators or text utilities in your browser. Inputs and results are not automatically sent. Prepare result for chat is an explicit separate action. Use the same currency and time period across related inputs. Scenario results are not verified revenue or forecasts.
3. **Automation briefs:** Choose from 24 workflow starting points. A brief asks the assistant to inspect supported triggers, tools, costs, failure behavior and permissions. Preparing it does not activate a schedule.
4. **Build queue:** Browse 186 proposed integrations. Each explains its needs and acceptance criteria. Prepare implementation brief starts a planning request; it does not install or connect the service.

Save tool stores up to 30 tool IDs in this browser. Fields remain while navigating the current tool session but are not promised to survive reload. If a prepared request would overwrite a draft, choose Add, Replace or Cancel. Backend cards initially show at most 60 matches; search or category filtering reaches the rest.

## Council, missions and activity

The named council buttons open dossiers and let you prepare a delegation or ask for actual status. Advisor gems are modeled objects; ambient movement does not mean they are running tasks. Mission briefs provide 16 quick general-purpose requests. Activity records actual chat requests in this page and whether a reply arrived or failed. It does not expose an invented live tool trace and is cleared on reload.

## Graphics and errors

Drag the scene to change its view; Reset view restores the default. Settings retains still motion and quality choices. An unsupported GPU shows “Still view · simplified rendering”; this is an honest fallback. If all graphics fail, conversation remains available.

“Ready when you are” is an idle state. Waiting/thinking follows an actual pending request; listening follows the microphone state; speaking follows output state. An error does not count as completion. Restore message to retry puts failed text back in the composer without sending automatically. If a catalogue fails to load, chat still works.
