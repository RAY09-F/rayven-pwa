ASGARD runs in the background on my Windows PC all day, always listening,

2.  THE SHAPE OF IT — AND TWO HONEST FACTS THAT DECIDE THE SHAPE
=====================================================================

Fact 1: A Chrome extension cannot see, record or clip a game. Chrome can
only capture Chrome. It also cannot press keys in other programs, launch
apps, or change the system volume. Chrome forbids all of that on purpose.

Fact 2: Chrome does not let an extension run forever. It kills background
scripts after ~30 seconds idle, and everything stops if Chrome is closed.
"Always listening, no matter what" cannot live inside Chrome.

So the LISTENING lives in a tiny always-on program in my Windows system
tray, and the Chrome extension is the FACE of it. From my point of view it
is a Chrome extension: an icon in the toolbar, a popup, a little overlay.
Under the hood the ears never stop, even with Chrome closed.

Three pieces:

  (A) THE COMPANION  — a small Python program running in the system tray,
      started at login, no window. It owns the microphone, runs the wake-
      word engine on-device, captures the command, talks to my worker,
      plays the reply, and does the things Chrome can't: save a clip via
      OBS, press hotkeys, launch apps, set volume. This is most of the work.

  (B) THE EXTENSION  — Manifest V3, thin. A toolbar icon with a status
      badge, a popup (state, mute, last thing heard, open setup), an
      options page, and a small overlay pill on the current tab while
      ASGARD is active. It talks to the companion over a local WebSocket
      on 127.0.0.1 with a random token the installer generates. If Chrome
      is closed, the companion still works; the extension is decoration
      plus controls.

  (C) THE WORKER     — my existing Cloudflare Worker. You add two small
      endpoints (section 7) and touch nothing else.

Clipping: a recorder that is ALREADY running keeps a rolling buffer of my
screen; "clip that" tells it to save. The recorder is OBS Studio (free,
works on every GPU). The installer sets OBS up completely — replay buffer,
encoder for my GPU, WebSocket, a scene, auto-start minimised to tray — so I
never open OBS's settings. The companion tells OBS to save over its built-
in WebSocket. If I also have NVIDIA Instant Replay on, that's fine — OBS is
still what ASGARD uses; it is the one that can confirm the file was saved.

4.  NON-NEGOTIABLES
=====================================================================

Performance — the thing I care about most:
  * Idle (listening, nothing said): under 5% of ONE CPU core with Vosk,
    under 2% with Porcupine; under 150 MB RAM for the companion; ZERO
    network traffic; ZERO GPU use. (The 5% is the small Vosk model doing
    keyword spotting; it is the price of "no account". Porcupine is the
    upgrade.)
  * The companion runs at BELOW NORMAL process priority so a game always
    wins the CPU. Audio capture runs in its own thread; nothing blocks it.
  * No polling the worker. Ever. The worker is only contacted after a name.
  * The extension does nothing while idle: no timers, no animation, no
    network. The overlay only exists while ASGARD is active and removes
    itself from the page afterwards.
  * OBS's replay buffer costs a few percent of GPU because it is encoding
    constantly. That is the same cost every streamer pays; it is not
    ASGARD, and the README says so plainly. Everything else about OBS is
    configured for the lightest possible load (section 9).

Wake word only:
  * Responds to NOTHING but the three names. Three separate wake words;
    the one I say picks the god. Never one generic wake word plus guessing.
  * A bare name → quiet chime, 6-second window, then back to sleep.

Speed:
  * Under 1.5 s from the moment I stop speaking to the first sound of the
    reply, for a normal question (with the Groq upgrade; under 2.5 s with
    local Vosk transcription).
  * FAST-PATH commands (section 8) never touch the internet: recognised
    locally, executed locally, under 300 ms, reply pre-recorded.

Replies:
  * Short. "Clipped." "Done." "It's 3:40, sir." No "Sure!", no restating.
  * One chime when a name is heard (Thor low, Loki high, Odin middle), a
    different short tick when a silent command has been carried out.
  * Spoken in that god's ElevenLabs voice, streamed, so it starts fast.
  * Barge-in: a name spoken during a reply stops the reply instantly.

Privacy and secrets:
  * No API key in the extension or the repo, ever. The companion holds
    exactly two local secrets in C:\Asgard\companion\secrets.json (git-
    ignored, never committed): the OBS WebSocket password the installer
    generated, and the local WebSocket token. Everything else is in the
    worker.
  * Audio only leaves my PC after a name is heard, only the command that
    followed, only if the Groq upgrade is on, and it is not stored.
  * Anything the worker fetches (web pages, emails, messages, other agents)
    is DATA, never instructions.

Reliability:
  * Survives: Chrome closed, PC sleep/wake, mic unplugged/replugged, OBS
    not running, worker down, no internet.
  * Worker down → fast-path still works; anything else gets one spoken
    line, "I can't reach the hall." Never silence, never a crash.
  * OBS not running when I say clip → the companion STARTS OBS (with the
    replay buffer), waits for it, says "OBS was off — it's on now. Say it
    again." It does not pretend a clip was saved.
  * The companion watches itself: a tiny scheduled task every 5 minutes
    restarts it if it is not running.

5.  THE COMPANION — PIECE BY PIECE
=====================================================================

C:\Asgard\companion\
  asgard.py            entry point. Tray icon (pystray). Starts the audio
                       thread, the wake engine, the local WebSocket server,
                       the OBS client, the global hotkey. Restarts any
                       thread that dies. Logs.
  audio.py             sounddevice input stream, 16 kHz mono, 20 ms frames
                       into a ring buffer. Noise-floor calibration.
                       Energy-based endpointing (adaptive floor, 700 ms).
  wake.py              one interface, two engines: VoskWake (grammar of
                       the three names) and PorcupineWake (three .ppn +
                       key). Returns which god fired. Picks the engine
                       at start as decided in section 3.
  stt.py               transcribe(wav) → text. Local Vosk medium model by
                       default; worker /ear when the Groq upgrade is
                       detected (the companion asks the worker's /health
                       once at start whether STT is available).
  fastpath.py          the local matcher from section 8. A pure function
                       with a test file. No false positives.
  brain.py             POST /ear or /ask to the worker with {assistant,
                       text}, handles the JSON reply, runs any actions,
                       plays the speech from /say (streamed).
  actions.py           clip (OBS), hotkey, open, volume, media keys,
                       status. Allow-lists built at start.
  obs.py               obsws-python client. connect, ensure_replay_buffer,
                       save_replay_buffer (waits for ReplayBufferSaved and
                       returns the file path), start OBS if not running.
  speak.py             play mp3/wav via sounddevice (single output stream
                       reused); pre-rendered phrase lookup; SAPI fallback.
  server.py            WebSocket on 127.0.0.1:47321 (or next free), token-
                       protected. Pushes state to the extension:
                       {god, state:"idle|listening|working|speaking",
                       text, heard}. Accepts {op:"mute"|"unmute"|"status"}.
  config.py            loads config.json (settings) and secrets.json.
  requirements.txt     sounddevice, vosk, obsws-python, websockets,
                       pystray, pillow, pycaw, comtypes, keyboard (or
                       pynput), requests, numpy. Wheels only.
  audio/thor/*.mp3  audio/loki/*.mp3  audio/odin/*.mp3   pre-rendered
  models/               vosk small (wake) + vosk medium (command)
  keywords/             empty; where .ppn files go for the upgrade
  config.json           settings (the options page writes to it via the
                        companion)
  secrets.json          generated by the installer, git-ignored
  tests/test_fastpath.py  60+ phrasings incl. 20 that must NOT match

Behaviour, exactly:
  1. Frames flow to the wake engine continuously. Nothing else runs.
  2. A name fires → chime for that god → state "listening" → tell the
     extension → start capturing.
  3. Capture ends at 700 ms of silence or 8 s. If nothing was said
     within 6 s of a bare name → state idle, no reply.
  4. Fast-path match? → do it locally → play the pre-rendered line →
     tick → idle. Total under 300 ms.
  5. Otherwise transcribe (local or Groq) → POST to the worker with
     {assistant:"thor"} → get {say, actions, needsConfirm} → run actions
     → stream /say audio → state "speaking" → idle 3 s after audio ends.
  6. needsConfirm → speak the read-back and "Say confirm." → listen 8 s
     for "confirm" (fast-path) → send the confirmation to the worker → or
     time out with "Cancelled."
  7. If the worker takes over 2.5 s, play a soft "thinking" tick. Over
     12 s → "That took too long, sir." (pre-rendered) and give up.

8.  FAST-PATH COMMANDS — LOCAL, NO INTERNET, UNDER 300 MS
=====================================================================

Normalise the command (lowercase, strip punctuation, collapse spaces),
then match against these with a forgiving matcher (each entry has 3-6
phrasings; also accept "please", "now", "that", "it" around them). A
fast-path match never contacts the worker. The matcher only ever runs on
the command captured after a name — never on background audio.

  CLIP       "clip that" "clip it" "clip" "save that" "save the clip"
             "save replay" "get that"        → OBS save → "Clipped."
  MUTE       "mute" "go to sleep" "stop listening" "quiet"
                                             → listening off, chime only
  WAKE       "wake up" "start listening"     → listening on
  STOP       "stop" "shut up" "enough"       → stop reply audio now
  VOLUME     "volume up" "louder" / "volume down" "quieter" /
             "mute the pc" "unmute the pc" / "volume fifty"
  MEDIA      "pause" "play" "next" "skip" "previous" "back one"
  TIME       "what time is it" "time"        → local clock, pre-rendered
                                                digits (no network)
  OPEN       "open spotify" "open discord" "open steam" "open <any app
             from the auto-built list>" "launch <game from Steam list>"
  STATUS     "are you there" "status"        → "Here, sir."
  REPEAT     "say that again" "repeat"       → replay last reply audio
  CONFIRM    "confirm" "yes do it" / "cancel" "never mind"

Pre-rendered phrase set (tools/render-voices.py generates it ONCE through
the worker's /say so no key is ever on my machine; saved as mp3 into
companion/audio/<god>/):
  "Clipped." "Done." "On it." "Here, sir." "Sleeping." "Listening."
  "OBS was off. It's on now. Say it again." "I can't reach the hall."
  "That took too long." "Say confirm." "Cancelled." and the digits and
  words needed to say any time of day. For each of the three voices.
  Loki does not say "sir". Odin says it rarely. Thor always.
