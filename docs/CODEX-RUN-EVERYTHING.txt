=====================================================================
1. HOW TO READ AN ENTRY
=====================================================================

Every entry looks like this:

    0603  The cancel-everything audit tool
          What: ...        <- the spec
          Does: ...        <- the acceptance criterion
          Cost ...         <- ignore unless it says a paid service
          First step: ...  <- a hint at the smallest version

Build the smallest complete thing that makes "Does:" true. Not the
grandest. If "What:" describes five features, build them as five small
commits under the same number. If an entry references another number
("0006 pairs with 0845"), read that one too. If several numbers
describe the same thing (0304, 0154 and 0533 are all the health page),
build it once and mark all of them done with the same note.

Find an entry fast:  grep -n "^0603  " docs/EVERYTHING.txt
Read it:             sed -n '/^0603  /,/^0604  /p' docs/EVERYTHING.txt

=====================================================================
2. THE PER-ENTRY PROTOCOL — every entry, every time
=====================================================================

  1. Read the entry in full, plus any entry it references.
  2. Check docs/INVENTORY.md and the code for anything that already
     does part of it. Reuse. Never build a second version of a thing
     that exists; extend the existing one.
  3. Implement. Complete files. Follow docs/CONVENTIONS.md (you write
     it in Phase 0): where tools live, how they register, how routines
     register, KV key patterns, secret naming, test locations.
  4. Prove it. Every entry gets one of:
       - a unit test under tests/ that runs with `npm test`, or
       - a check script scripts/check-NNNN.sh that a human can run
         and that prints PASS or FAIL, or
       - for pure config/docs: a line in PROGRESS.md saying how to
         see it.
     A tool entry is not done until the tool can be called end to end
     through the same path Rayan uses (Telegram or the hub), with a
     real reply, in the test tier / with mocks where a paid call would
     otherwise happen.
  5. Log it. Append ONE line to docs/PROGRESS.md under the phase:
       NNNN | done | files touched | how to test | note (reading
       taken, anything deferred)
     Or `blocked-human` with the NEXT-STEPS reference, or `skipped`
     with the one-line reason (only rules 0.4–0.10 justify a skip).
  6. Commit: `git add -A && git commit -m "NNNN: <entry title>"`.
  7. Next entry in manifest order. Do not skip ahead for fun.

Time-box: if an entry is taking more than ~45 minutes of your effort,
ship the smallest version that makes "Does:" true, note what was cut,
and move on. The list is a pantry, not a plate.

=====================================================================
3. THE PHASE PROTOCOL
=====================================================================

At the START of a phase:
  - `git checkout main && git pull` (never reset), then
    `git checkout -b phase-N`.
  - Read the phase's entry list in docs/BUILD-MANIFEST.txt.
  - Write the phase header into PROGRESS.md with the date.

At the END of a phase (all entries done, blocked-human, or skipped):
  - Run the full test suite. Fix what you broke.
  - Deploy the Worker: `wrangler deploy` (the frontend deploys itself
    from git; the extension is reloaded by Rayan — write that step).
  - Run scripts/smoke.sh (you build it in Phase 1; until then, curl
    /health and send one Telegram test through the approval gate).
  - If smoke fails: `scripts/rollback.sh` (Phase 1, entry 0306),
    confirm smoke passes on the previous version, write
    docs/INCIDENT-<date>.md with what failed, and STOP the phase
    there. Do not push a broken main.
  - If smoke passes: merge phase-N into main (a merge commit; never
    force), push, and write the phase summary at the top of
    PROGRESS.md: entries done / blocked / skipped, what Rayan must do
    now (pointing at NEXT-STEPS-HUMAN.md), and the exact line to paste
    to start the next phase.
  - Then stop and report in one paragraph. One phase per session
    unless Rayan says otherwise.

6. STOP CONDITIONS — the only reasons to stop mid-phase
=====================================================================

  - A deploy fails and the rollback also fails to bring /health back.
    Write docs/INCIDENT-<date>.md (what changed, what you tried, the
    exact error text, the commit that last worked) and stop.
  - The repo is not what this file assumes (no Worker, no wrangler.toml,
    a different project). Write what you found in PROGRESS.md and stop.
  - You are on the Chromebook and a required step needs the PC. Write
    the step to NEXT-STEPS-HUMAN.md and continue with entries that do
    not need it; stop only if none remain.
  - Rayan's usage limit is reached. Commit what is done, update
    PROGRESS.md so the next session resumes at the exact entry.

Everything else — an ambiguous entry, a missing secret, a paid API you
cannot call, a test that needs a mock — is handled inside the protocol
without stopping.
