# The Asgard Visual Language

This is the house style for Asgard's three halls. It exists so that every
visual change lands in the same world instead of ten different ones, and so
that nothing beautiful ships that a 2.7 GB Chromebook cannot actually run.

Rayan has zero coding experience. He is the only person who can see pixels —
you cannot. Everything here is written so you can build to spec without asking
him to judge things he has no vocabulary for, and so that when you DO need his
eyes, you ask for one concrete thing at a time.

## The one-sentence version

Every god's hall is a dark, still room containing **one real modeled object
that holds light**, five gem-like advisors arranged around it, and readable
HTML text that never lives inside the 3D scene.

---

## 1. The arc core is real geometry. Always.

"Arc core" means the modeled centerpiece of a god's interface: an object with
actual vertices, materials, lighting and state-driven animation.

- A glow, a sprite, a flat logo, a particle cloud or a pre-rendered image is
  **not** an arc core. Effects may surround it; the object underneath must stay
  recognizable as a solid thing with volume.
- When motion is disabled, the core is still lit and still dimensional. Still
  mode removes movement, never depth.
- A static image fallback exists only for when WebGL fails outright. It is a
  safety net, never the deliverable.

**Per-god geometry** — these identities are fixed:

| God | Core | Never |
|---|---|---|
| THOR | A recognizable hammer assembly, held inside interlocking curved shells | A lightning bolt alone, a flat icon |
| LOKI | An angular faceted relic framed by an asymmetric looping structure | A snake, a helmet with horns as a *likeness* |
| ODIN | A nested iris / aperture ring, opening through toroidal pieces | An eyeball, a face |

Generic objects are fine and encouraged: hammer, spear, horned crown as a
*shape*, gems, rings, birds, storm. **No character likenesses, no film imagery,
no logos, ever.** Names are text labels only.

The fourth realm has **no core file and no core module** — its look stays
inside the engine and is never named in a public filename, comment, fetch,
label, count or route. When that realm is active the cores layer stays
disposed and the engine's existing treatment carries the centre. If you are
building something that would reveal it, you are building the wrong thing.

---

## 2. The house direction: The Impossible Relic

Of the twenty directions in the design book, this is the one that is being
built. It was chosen because Rayan approved its colors directly, it is the
book's own recommended first prototype, and its geometry simplifies gracefully
when the Chromebook struggles.

**Materials:** opalescent resin, polished edges, brushed metal mounts, dark
polished floor with a restrained reflection. Not chrome, not glass, not neon.

**Structure:** a solid faceted core sitting inside an interlocking curved
shell, on a stepped circular plinth, with five advisor gems on their own small
plinths in a ring around it, connected to the core by thin light tethers.

**Palette — base (all three halls share these):**

--asg-plum       #292337   /* mid-dark structural mass                */
--asg-void       #0B0A12   /* the room behind everything              */
--asg-silver     #C8D1DC   /* metal mounts, rims, plinth edges        */
--asg-petrol     #285E6B   /* cool shadow tone, tether base           */
--asg-uv         #7965CF   /* ambient bounce, atmospheric haze        */
```

**Palette — per-god accent (the core's own light):**

```
THOR   core   #EAF8FF  cold white     rim  #66C7FF  storm blue
LOKI   core   #E7C24A  citrine        rim  #D8AF5C  deep amber

## 3. Text and controls live in HTML. Never in the scene.

This is the rule that keeps the product usable when the graphics fail.

- The transcript, the composer, every panel, every label, every button: HTML
  over or beside the canvas.
- Selecting a modeled object opens readable HTML. Essential text is never baked
  into a texture, never rendered as 3D type, never placed on a moving surface.
- Keyboard focus lives on the **HTML advisor list**, and the gem mirrors it —
  the canvas is never the only way to reach anything.
- Labels that track 3D positions update at ~15 Hz, transform-only, with no
  layout reads and no per-frame allocation. Smooth enough to read as attached;
  cheap enough to be free.

## 4. Panel mapping — keep every one of them

The hall already has these panels and they all keep working. In this direction
they take these forms:

| Panel | Form in this world | Rule |
|---|---|---|
| Top bar | A thin fixed horizon rail | FPS, verts, link latency, mute, CTRL+K stay reachable; diagnostics may hide in a tray |
| Fourth panel (FIELD LOG / THE LEDGER / COUNSEL) | Flat ceramic cards, timestamped | Per-god name — Thor FIELD LOG, Loki THE LEDGER, Odin COUNSEL. Observable actions and real recommendations only — never invented reasoning |
| THROUGHPUT | Four calibrated arcs | Keep the defined units. Undefined = "Not configured". Unavailable = "Unavailable" |
| CHANNEL | A broad fixed reading pane | Full transcript, speaker labels, input, send, stop |
| SUBSYSTEMS | Folded-edge tiles | Explicit OPEN / READY / HELD states |
| LINKED | Labeled seam joins | worker, KV, R2, extension, tool count, with real observation times |
| RAVEN SIGHT | A geometry-inspection tray | render path, elements drawn, FPS, worker round-trip |
| Bottom bar | A fixed voice rail | mic, rate, pitch, and the three persona states |

A task has states — queued, running, waiting, completed, failed. It does not
have an invented progress percentage, and it never displays private model
reasoning.

Odin's paper trading carries a conspicuous **PAPER / SIM** label everywhere a
number appears. No exceptions, no small print.

## 5. Motion

Motion is authored, not simulated. A few deliberate movements beat many
continuous ones.

- **Idle:** slow. A breath of scale, a few degrees of drift over 20–40 seconds.
  The room is never dead still and never busy.
- **Listening:** the room leans in — structure tightens toward centre, ambient
  dims slightly.
- **Thinking:** one slow build. Loki's shell rotates a quarter turn; Odin's
  iris closes; Thor's shells draw in. It resolves; it does not loop frantically.
- **Speaking:** the core's emissive tracks speech level. Peaks produce one
  discrete event — a strike, a ring, a flare — not a strobe.
- **Selection:** picking an advisor lights **only** its tether and its tool
  markers, and settles everything else. This is the signature interaction: the
  route from core to advisor to tool becomes physically visible.
- **Realm switch:** one 600 ms wipe. One cut, not a sequence.

Every animation has a hard deadline. If it has not finished by then it
force-completes. A thrown frame must never leave Rayan with a mute assistant or
a half-drawn room.

`prefers-reduced-motion` and the visible **still mode** toggle both freeze
motion while keeping the core lit and dimensional. State changes then read as
label changes, not camera moves. The still-mode control is injected by the FX
layer, the same way the mute control is — it is never a new edit to the hall.

## 6. The performance budget IS the art direction

Every rule below was earned by a real bug on this exact machine.

- **One renderer.** The cores render inside the FX engine's existing WebGL
  context — no new canvas, no second full-screen context. The hall already
  holds a GL context of its own; a third surface on 2.7 GB of RAM is exactly
  where context loss happens.
- **Frame-rate floor: 45 fps with the governor engaged.** 55 is the target for
  a bare spike page with nothing else running. Between 45 and 55 the governor
  does its job and that is acceptable; below 45 on the Chromebook, drop that
  page a tier by default and tell Rayan you did.
- When a core is active, the room backdrop behind it drops to its static tier.
  Two full-screen animated layers plus a lit model is the combination that
  breaks this machine.
- DPR capped at 1.5. Never resize a canvas inside the frame loop.
- Clamp `requestAnimationFrame` deltas to ≥ 0 — a negative first-frame delta
  once produced NaN and silently killed a whole wake sequence.
- Write off-screen tests positively (`if (x > -8 && x < w + 8)`) so NaN is
  rejected rather than passed through.
- Clamp every gradient radius to a finite positive number.
- **Never** put a CSS `filter` or `backdrop-filter` on an animated layer. Glass
  panels use a pre-rendered blurred snapshot. This halved the frame rate once.
- Pre-render static layers once to an offscreen canvas.
- Additive blending only on small layers, never full-screen.
- Pool particles. No per-frame allocation, ever.
- Reuse geometry and materials across gems; instance the tool markers.
- Dispose geometry, materials and textures when leaving a realm — hiding is not
  releasing. Switching realms three times in a row must not degrade.
- Quality governor: below 45 fps for 3 seconds, drop one tier — halve
  particles → bloom off → DPR 1 → static backdrop. Never below a lit static core.
- Render tiers: WebGL2 → WebGL1 (write shaders once in GLSL ES 1.00) → a 2D
  fallback that still reads as a composed object.
- Handle `webglcontextlost` / `webglcontextrestored` on every page.
- `?fx=0` gives a plain working page. `?debug=1` shows FPS, tier and RENDER PATH.
- **localStorage holds three keys only: mute, quality tier, and still mode.**
  Never a persona id, never conversation state. (The hub's existing
  boot-sequence-seen flag predates this and stays; do not add a fourth.)
- Three.js loads from the three CDN mirrors the project already uses
  (jsdelivr → unpkg → esm.sh), pinned to one exact version, with a graceful
  failure path if all three are blocked.

Targets on real hardware, measured with the Linux terminal closed and read back
by Rayan — never asserted by you: **45+ fps Chromebook (55 on a bare page),
30+ fps phone.** A dark room full of small transparent effects can cost more
than one larger opaque model — complexity is not polygon count.

(function(){
  var halls = ['thor','loki','odin'];

  function fit(){

    var s = Math.min(w/1920, h/1080);
    document.querySelectorAll('.stage').forEach(function(st){ st.style.transform = 'scale(' + s + ')'; });

  });

  /* drifting dust */
  var raf = null;
  function startDust(){
    if (raf) cancelAnimationFrame(raf);
    if (matchMedia('(prefers-reduced-motion: reduce)').matches) return;
    var st = document.querySelector('.stage.active'); if (!st) return;
    var cv = st.querySelector('canvas.dust'); var ctx = cv.getContext('2d');
    cv.width = 1920; cv.height = 1080;
    var tone = st.classList.contains('hall--loki') ? [200,255,225] :
               st.classList.contains('hall--odin') ? [255,225,170] : [190,215,255];
    var ps = []; for (var i=0;i<70;i++) ps.push({
      x: Math.random()*1920, y: Math.random()*1080,
      r: .6 + Math.random()*1.8, v: .1 + Math.random()*.35,
      dx: (Math.random()-.5)*.12, a: .08 + Math.random()*.3, ph: Math.random()*6.28 });
    var last = 0;
    function tick(t){
      var dt = Math.max(0, Math.min(50, t - last)); last = t;
      ctx.clearRect(0,0,1920,1080);
      for (var i=0;i<ps.length;i++){ var p = ps[i];
        p.y -= p.v * dt * .06; p.x += p.dx * dt * .06;
        if (p.y < -4){ p.y = 1084; p.x = Math.random()*1920; }
        if (p.x < -4) p.x = 1924; if (p.x > 1924) p.x = -4;
        var tw = .55 + .45 * Math.sin(t*.001 + p.ph);
        ctx.beginPath(); ctx.arc(p.x, p.y, p.r, 0, 6.283);
        ctx.fillStyle = 'rgba(' + tone[0] + ',' + tone[1] + ',' + tone[2] + ',' + (p.a*tw).toFixed(3) + ')';
        ctx.fill();
      }
      raf = requestAnimationFrame(tick);
    }
    raf = requestAnimationFrame(tick);
  }

  /* cursor light */
  document.querySelectorAll('.stage').forEach(function(st){
    var cl = st.querySelector('.cursorlight');
    st.addEventListener('pointermove', function(e){
      var r = st.getBoundingClientRect(); var sc = r.width/1920;
      cl.style.opacity = 1;
      cl.style.left = ((e.clientX - r.left)/sc - 260) + 'px';
      cl.style.top  = ((e.clientY - r.top)/sc - 260) + 'px';
    });
    st.addEventListener('pointerleave', function(){ cl.style.opacity = 0; });
  });

  var initial = (location.hash || '').replace('#','');
  var q = new URLSearchParams(location.search).get('hall');
  show(halls.indexOf(q) >= 0 ? q : (halls.indexOf(initial) >= 0 ? initial : 'thor'));

7.0  THE TOOLBOX MECHANISM (build first — this replaces 6.1)
     A god with 300 tools in front of him picks badly and pays for every one
     on every message. So:
     - Tool metadata — group, permission level, taint (does it return
       outside content), budget, timeout, source label — lives in a PARALLEL
       registry src/tools/meta.js keyed by tool name. Never inside the schema
       object sent to Anthropic (the API rejects unknown fields).
     - CORE per god: at most 40 tools, always sent, in the master order
       (Rule 6). List each god's CORE by exact tool name in docs/CORE.md.
       Thor: conversation, memory, calendar/to-dos, web search, weather,
       maps, Spotify, browser, texts/calls (hard-confirm), delegate,
       routines, find_tools. Loki: calendar, reminders, to-dos, memory,

       groups — names and schemas unchanged (Rule 2 is about renaming, not
       grouping) — and the first-message keyword rules MUST open them for the
       requests they serve today. Smoke additions: "play some music", "open
       youtube.com", "text Jay" each work without an extra turn.
     - find_tools({ query }): a meta-tool. It searches the whole catalogue
       (name, description, group) and returns the ten best matches with one
       line each, and OPENS their groups for the rest of this conversation:
       the open-group list rides in the history object (Rule 5a) and the next
       model call includes those groups' schemas, appended after CORE in the
       master order. One cache miss per group opened — accepted. Groups also
       open automatically at the FIRST message of a conversation by keyword
       rules (no model call). A group CLOSES after 20 turns in which none of
       its tools was called (counter in the history object) and on history
       compaction — Telegram chats never restart, so without this the whole
       catalogue would eventually ride on every turn.
     - Measure CORE size with the Anthropic count_tokens endpoint, not by
       guessing. CORE must stay under ~10k tokens per god.

       call find_tools first, then use what it opens. Never say you can't do
