What changed in the phone release

Fast replies now store generated audio directly in the existing R2 bucket, with a 15-minute URL lifetime and scheduled cleanup. R2 makes a completed write immediately readable; the legacy KV path remains a fallback. This removes a potential audio-delivery delay, but it does not prove storage caused your previous pauses.

Both the owner-update path and the older outbound-call path use ElevenLabs Flash for phone speech. The older path also now uses Haiku and a one-second speech-end timeout. Owner calls already used those faster model and speech-end settings. Voice generation now has a five-second request deadline before the existing backup-voice handling takes over.

Phone replies are instructed to lead with the answer, use natural contractions and keep ordinary answers short. Exact greetings, thanks and goodbyes skip the language-model round trip. Real questions still go through the model and tools; nothing fabricates a result to sound faster. Thor, Loki and Odin retain their configured voices and switching behavior. No turn-taking announcer was added.

The paired phone page now shows recent server-processing, model/tool and voice/storage timings. These exclude speech recognition, carrier delay, playback and some request/ledger overhead. They are not end-to-end measurements. No live phone call has been measured for this release, so instant or one-to-two-second replies are not verified.

This remains turn-based Twilio speech gathering and full-audio playback. Speaking over the AI to interrupt it and true streaming conversation require a separate streaming voice implementation. Tool-heavy questions can still take longer than simple conversation. The current phone tool allowlist is narrower than the web app's tools.

Verification and rollback

The phone changes have automated tests for binary audio delivery, expiry, cleanup scope, fast voice settings and conservative quick replies. The full project test suite passed before deployment; release details are recorded with the code. No actual phone latency, physical fan color or Fortnite performance result should be inferred from unit tests.

If new call audio fails, revert the phone code to the preceding release while retaining the current Durable Object bindings and paper-ledger migration. Never revert to the old KV-only trading write path. The existing backup voice remains available if persona speech generation fails.
