# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ASGARD (formerly RAYVEN) — Rayan's personal AI system: three personas sharing one brain — THOR (personal assistant, the default, formerly RAYVEN), LOKI (to-dos/reminders/wellbeing), ODIN (business/revenue/strategy) — built as a Cloudflare Worker backend with a browser extension for computer control and a web/PWA frontend. It talks to Rayan over a private web interface and Telegram, runs Claude (Anthropic) tool-calling to take real-world actions (texting, calling, Spotify, browser control, maps, web research), and runs autonomous background jobs (proactive check-ins, morning briefings, a self-code-check, per-persona autonomy, and web/product monitoring) off a 5-minute cron trigger. See README-ASGARD.md for operator setup.

**Persona rules that must not regress:** `src/lib/personas.js` is the single registry — derive every persona list from `Object.keys(PERSONAS)`, never hand-write a parallel id array. Tool allow-lists are enforced in the dispatcher (`callClaudeWithTools`), not just prompts. `send_text`/`make_call` are hardcoded to confirm (`HARD_CONFIRM_TOOLS`). Telegram webhooks ack immediately with `update_id` dedupe — never await a full turn in the webhook response. The JARVIS federation contract (worker URL, RAYVENN_RAYAN_BOT on `POST /`, `/agent/query` + HMAC) must never change without telling Jay first. index.html contains a concealed frontend-only region between paired `⟦PROJECT-H⟧` comment markers: it must stay out of every registry/prompt/tool description, and any code path that serves source to a model must strip it (see `redactConcealedRegions` in `src/lib/checkin.js`) — do not name its contents in any other file.

## Commands

There is no package.json, bundler config, lint config, or test suite in this repo — it is deployed straight from source via Wrangler.

- `npx wrangler dev` — run the worker locally
- **The live Worker is named `asgrard-backend`** (misspelled on Cloudflare — do not "fix" it casually), at `https://asgrard-backend.rayanfahil2.workers.dev`. It was renamed from `rayven-backend` on 2026-08-15; that old name no longer exists and its URL returns Cloudflare error 1042. Secrets, the workers.dev URL, and Telegram webhooks all attach to the script **name**, so `name` in `wrangler.toml` must match exactly — deploying under a name that doesn't exist silently creates a *second, empty* Worker with no secrets while the real one keeps serving. A rename means: re-add all 17 secrets, re-point the Telegram webhook (`GET /debug-telegram-webhook?set=1` does this from inside the worker, no token handling), and update `BACKEND_URL` in all five live `index.html` files plus `background.js` (the Chrome extension) and `src/lib/spotify.js` (the OAuth redirect URI).
- `npx wrangler deploy` — deploy to Cloudflare (entrypoint is `src/index.js`, per `wrangler.toml`). This also publishes every page in `public/`: `GET /` 302-redirects to `/thor/` (the front page since 2026-08-15); the ASGARD hub is served at `/hub/` from `public/hub/index.html`, which is a **copy** of the repo-root `index.html` — after editing `index.html`, re-copy it to `public/hub/index.html` before deploying, or the live hub silently stays stale.
- `npx wrangler tail` — stream live logs from the deployed worker
- `npx wrangler secret put <NAME>` — set a secret (API keys live in Cloudflare secrets, not in this repo)
- `node --check <file>` — quick syntax validation for a single JS file (no build step exists to catch syntax errors otherwise)

## Architecture

### Entry point and legacy file

`wrangler.toml` points `main` at `src/index.js` — that is the real, deployed entrypoint. **`worker.js` at the repo root is a pre-refactor monolith kept as a backup/reference; it is not wired into `wrangler.toml` and does not run.** Do not add features there. The one place `worker.js` is still live is content, not code: `runCodeCheck` in `src/lib/checkin.js` pulls `worker.js` and `index.html` fresh from GitHub every day and asks Claude to review them for bugs — so `worker.js` should stay in sync enough to be a meaningful diff target, but new backend logic always goes in `src/`.

### Per-assistant product pages (`public/thor/`, `public/loki/`, `public/odin/`)

Since 2026-08-15 each persona also has its own standalone single-file product page, served by the worker's static assets at `/thor/` (Storm Forge — Mjolnir centerpiece, lightning wake), `/loki/` (Trickster's Court — jester shatter/reassemble wake, asymmetric tilted-card layout), and `/odin/` (High Seat — diagonal Gungnir, rune-ignition/Bifrost/ravens wake, KPI lintel). These are separate files from the hub `index.html` and do NOT contain the concealed region. Rules that must not regress:

- **One engine, three shells.** Each page embeds the ASGARD VOICE ENGINE between `/* ═══ ENGINE-BEGIN ═══ */` and `/* ═══ ENGINE-END ═══ */` markers, and the block must stay **byte-identical** across all three files (`diff <(awk '/ENGINE-BEGIN/,/ENGINE-END/' a) <(awk ...b)` must be empty). Fix a bug inside the markers in one file, then copy the whole block to the other two. Page-specific behavior goes only through `window.ASSISTANT` (config) and `window.SHELL` (adapter) defined above the block.
- Wake matching is multi-variant + fuzzy (greeting word + misheard-name lists + Levenshtein) — never reduce it to one exact phrase; that broke detection once before. Bare-name wake is off by default (`bareNameSafe` guards "for"/"low key" false wakes); "wake up" alone never wakes. Double-clap detection (adaptive RMS baseline, 150–700ms gap) has a sensitivity setting and a tab-visibility guard so only the visible page wakes.
- The pages send `{assistant: "<id>"}` to `POST /` (the router accepts `persona` or `assistant`). Scenes are classic `THREE.WebGLRenderer` + `EffectComposer`/`UnrealBloomPass` from three@0.170 via import map — same no-WebGPU rule as the reactor. Verify changes with the Playwright harness in the scratchpad pattern (serve `public/`, screenshot, assert bright-pixel fraction on the canvas region — never `drawImage` from the live WebGL canvas).
- Panels only ever show real backend data (`/kpi`, `/goals`, `/clipping`, `/calendar`, `/todos`, `/loki/brief-latest`, `/odin/reports`, `/permissions/all`, `/spotify/now-playing`, `/browser/status`, `/history?persona=`, `/memory?persona=`) or honest empty states — never fabricated numbers. `src/lib/reports.js` owns LOKI's scheduled daily brief and ODIN's recurring report (both off until a time is set via `/assistant-config`).

`index.html` is the frontend PWA — the full ASGARD HUD (lock screen + boot cinematic, a classic-WebGL reactor with three persona forms on a turntable, per-persona HUD languages, command palette, alert mode, inspection bay, memory map, ops floor, camera-based gesture control, and the concealed marked region). Rayan owns visual/UI direction on it; the previous version is preserved at `index-pre-asgard-backup.html`. Deployed via `[assets]` in `wrangler.toml` from `public/hub/index.html`, served at `/hub/` (a copy — re-copy after every edit before deploying; `GET /` redirects to `/thor/` since 2026-08-15); `run_worker_first = true` is required there or Cloudflare's asset handler claims `/` for every HTTP method, not just GET, silently 405ing chat and the Telegram webhook. Repo of record: `github.com/RAY09-F/rayven-pwa` (public — the Project H markers are NOT secret from humans reading that repo, only from the in-app personas and the code-check). Frontend verification lives as a Playwright suite pattern (serve the file statically, mock the backend origin, assert on DOM/canvas) — rebuild that harness rather than eyeballing changes.

**Reactor rendering — do not reintroduce `THREE.WebGPURenderer`.** It was tried first for the reactor/bay/projection and is broken: on any machine without a real WebGPU adapter (most of them), it silently falls back to an internal WebGL2 path whose Node-material auto-compiler requires a per-vertex `uv` attribute for textured Points that plain point sprites never carry — draw calls happen, vertex counts and FPS report fine, but literally zero pixels paint. The fix (now live) is classic `THREE.WebGLRenderer` + a hand-written GLSL `ShaderMaterial` (`gl_PointSize`/`gl_PointCoord`, no node-graph compilation) — the same technique already proven working before the WebGPU rewrite. Verify any renderer change by checking actual screenshot pixels, not a `drawImage()`-from-canvas probe (that has a read-timing false-negative against a live WebGL context) and not just the forced `?reactor=2d` fallback path (that was the original testing gap that let this bug ship).

### Request flow (`src/index.js`)

`fetch()` is a manual if/else router (no framework) handling both a debug/status route family (`/agent/log`, `/activity`, `/notifications`, `/monitors`, `/memory`, `/todos`, `/permissions`, various `/debug-*`) and the actual chat endpoint (`POST /`, plus Telegram webhook traffic detected via `body.message.chat`). Both channels converge on the same logic: load history from KV, run `callClaudeWithTools` (in `src/lib/tools.js`), save the reply back to history, and either return JSON (web) or send a Telegram message.

`scheduled()` fires every 5 minutes (`wrangler.toml` cron) and kicks off four independent subsystems in parallel via `ctx.waitUntil`, each deciding for itself whether it's actually due by checking its own "last run" KV key — proactive check-in, morning briefing, code check, and the monitoring sweep (chained into a notification digest flush). This "check my own KV state" pattern is used consistently — follow it for any new scheduled subsystem rather than adding new cron expressions.

### Module layout (`src/lib/`)

Each file owns one integration or concern and is imported explicitly by whatever needs it — there's no central registry beyond `tools.js`:

- `personas.js` — the ASGARD persona registry (prompts, colors, tool allow-lists, memory/history key mapping, per-persona Telegram token + ElevenLabs voice env names, switch/wake phrases). Everything persona-scoped derives from here.
- `autonomy.js` — per-persona scheduled autonomy (LOKI nag engine with escalation, ODIN strategy pulse, THOR real-call integration self-check), capped 3/day each, plus the live `status:<persona>` keys behind `GET /status` and the `agent:autonomy:log` capped log.
- `roundtable.js` — two personas debate a topic server-side (`POST /roundtable`), each gives a standing, and the exchange is saved into both personas' memories.
- `tools.js` — the tool schema array Claude sees (`TOOL_DEFINITIONS`), the `executeTool` dispatcher, and `callClaudeWithTools` (the tool-use loop, max 14 iterations, persona allow-list enforced at dispatch). This is the hub: adding a new capability means adding a case to `executeTool`, a schema entry to `TOOL_DEFINITIONS`, an allow-list decision in `personas.js`, and importing the underlying function from its owning module.
- `kv-store.js` — conversation history (capped at `MAX_HISTORY` = 30 turns) and simple KV-backed lists (todos, content ideas).
- `memory.js` — long-term memory, persona-namespaced (THOR keeps legacy `memory:longterm`; LOKI/ODIN get suffixed keys): a KV array of facts per persona is the source of truth, embedded via Workers AI (`@cf/baai/bge-base-en-v1.5`) and indexed in one shared Vectorize index (results scope per persona because search only surfaces ids present in that persona's own array). Adding a near-duplicate fact marks the old one `supersededBy`. Only the most recent 15 memories are inlined per prompt. Reads/writes go through a version-stamped in-isolate cache (`<key>:ver`) because KV `get()` right after `put()` can return stale data and silently lose memories. Cross-persona sharing (`/memory/share`) copies with `sharedFrom` attribution so secondhand memories never read as firsthand.
- `permissions.js` — per-tool permission levels (`auto`/`notify`/`confirm`/`off`). `GATEABLE_TOOLS` lists which tools are gateable at all; `confirm`-level tools get queued in KV (`pending:current`) and only execute if the next user message reads as affirmative (`isAffirmative`).
- `activity.js` / `notifications.js` / `util.js` — the shared logging backbone. `util.js`'s `appendCappedLog`/`readCappedLog` is the generic "capped JSON array in one KV key" pattern reused everywhere (`agent:log` in `sibling-agents.js`, `activity:log`, `notif:log`, monitoring). `notifications.js` is the single choke point every background subsystem calls through (`notify()`) to reach Rayan — it handles priority, dedup/cooldown by `dedupeKey`, hourly rate limiting, and batches low/normal-priority items into digests instead of spamming.
- `monitoring.js` — the persistent watchlist (`watch_add`/`watch_list`/etc.). A watch target is auto-classified as `page` mode (URL — hash-diff the extracted text) or `search` mode (query — diff new result URLs). Relevance is filtered through a Claude call before anything reaches `notify()`, so routine/cosmetic changes never page Rayan.
- `sibling-agents.js` — the agent-to-agent protocol with Jay's JARVIS and Kevin's KEVOS: outbound `askSiblingAgent`, and the inbound HMAC-authenticated `handleAgentQuery` (`POST /agent/query`) with per-caller daily rate limiting and a `hops > 0` guard against chained queries.
- `checkin.js` — the three cron-driven jobs: proactive Telegram check-in, the 8am Pacific-time morning briefing (own timezone-aware scheduling via `Intl.DateTimeFormat`, not a fixed UTC offset), and the daily self-code-check that pulls `worker.js`/`index.html` from GitHub and asks Claude to flag issues.
- `browser.js` — the command queue the Chrome extension polls (`GET /browser/poll`, `POST /browser/result`); `enqueueBrowserCommand` blocks (polling every 500ms, ~20s timeout) waiting for the extension's result, `enqueueBrowserCommandNoWait` fires and forgets.
- `telegram.js`, `spotify.js`, `maps.js`, `search.js`, `comms.js`, `anthropic.js` — thin wrappers around their respective external APIs (Telegram Bot API, Spotify Web API + OAuth, Google Maps/Places, SerpAPI/Tavily, Twilio, Anthropic Messages API).

### Browser extension (`background.js` + `manifest.json`)

A Manifest V3 service worker that polls `/browser/poll` every ~6 seconds (`chrome.alarms`) for queued commands and executes them against the active tab: click/type by text match (`chrome.scripting.executeScript`), or exact-coordinate click/type via the `chrome.debugger` protocol (`Input.dispatchMouseEvent`/`dispatchKeyEvent`) for cases text-matching can't handle. Screenshots go through `chrome.tabs.captureVisibleTab`. Results are POSTed back to `/browser/result` keyed by command id.

### State model

Everything persists in one KV namespace (`RAYVEN_KV`) — there is no separate database. Conversation history is keyed per channel (`telegram:<chatId>`, `web:main`). Capped-array logs and lookup values (`permissions`, `todos`, `monitor:list`, etc.) are each a single JSON blob under a fixed key. When adding a new persistent feature, follow whichever existing pattern it resembles most (capped log via `util.js`, or a flat JSON blob like `todos`) rather than introducing a new storage convention.
